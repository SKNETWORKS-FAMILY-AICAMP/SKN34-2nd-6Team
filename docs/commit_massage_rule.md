# Commit 메세지 규칙

Commit 메세지는 코드 변경 내용을 설명하는 중요한 기록입니다.  
명확한 Commit 메세지를 작성하면 다음과 같은 장점이 있습니다.  

- 코드 변경 이력 이해
- 협업 과정 기록
- 문제 발생시 원인 분석
- 프로젝트 관리 효율 향상

|타입|설명|
|---|---|
|feat|새로운 기능 추가|
|fix|버그 수정|
|docs|문서 수정|
|style|코드 스타일 수정(기능변경없음)|
|refactor|코드 구조 개선|
|test|테스트 코드 추가|
|chore|기타작업(빌드 설정 등)|

앞으로 jira를 통해 프로젝트가 관리될 예정입니다. jira에서 본인이 할당받은 일의  
코드 네임도 앞에 같이 적어서 올리시면 됩니다.

- 예시
### 기능추가
>KAN-34 feat: 회원가입 기능 추가

### 버그 수정
>KAN-34 fix: 로그인 오류 수정

### 문서 수정
>KAN-34 docs: readme 수정

### 코드 리팩토링
>KAN-34 refactor : 로그인 로직 개선

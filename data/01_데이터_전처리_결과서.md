# 기부 중단 위험군 분류를 위한 데이터 전처리 결과 보고서


## 1. 보고서 목적과 분석 범위

### 1.1 목적

최근 1년 동안 기부하지 않았지만 과거 기부 경험이 있는 사람을 ‘기부 중단 위험군’으로 분류하기 위한 모델링 데이터를 구성한다. 분류 결과는 재참여 안내, 기부 성과 공유, 맞춤형 캠페인 등의 우선순위를 정하는 데 활용할 수 있다.

본 데이터는 동일 기부자를 여러 시점에서 추적한 패널 데이터가 아니므로, 타겟은 확정적인 ‘이탈’이 아니라 최근 1년 미기부 여부를 이용한 대리 지표로 해석한다.

### 1.2 머신러닝 정의

| 항목 | 정의 |
|---|---|
| 문제 유형 | 이진 분류 |
| 분석 대상 | `기부여부(GUBUN)` 1과 2 |
| 위험군 | `기부여부(GUBUN) = 2` |
| 모델 선정 지표 | Macro F1 (`RandomizedSearchCV` 기준) |
| 운영상 중점 지표 | `기부여부(GUBUN) = 2` Recall |
| 활용 방안 | 위험 확률이 높은 대상자부터 재참여 캠페인 진행 |

### 2.2 타겟 정의와 분석 대상 필터링

`기부여부(GUBUN)` 1과 2만 모델링에 사용하고, 분석 목적에 포함되지 않는 3은 제외했다.

| `기부여부(GUBUN)` | 의미 | 원본 건수 | 전체 비율 | 모델링 데이터 비율 | 처리 |
|---:|---|---:|---:|---:|---|
| 1 | 최근 1년 동안 기부함 | 3,023 | 60.46% | 66.97% | 유지 |
| 2 | 최근 1년은 기부하지 않았지만 과거 기부 경험이 있음 | 1,491 | 29.82% | 33.03% | 유지 |
| 3 | 현재 분석 범위 외 응답군 | 486 | 9.72% | - | 제외 |

모델링 데이터에서 1과 2의 비율은 약 2.03:1이므로, 정확도만 사용하면 소수 클래스 2의 탐지 성능을 충분히 반영하지 못할 수 있다.

## 3. 데이터 전처리 수행 내용

### 3.1 행 필터링과 특성 선정

1. `기부여부(GUBUN) = 3`인 486행을 분석 대상에서 제외했다.
2. 식별자, 검수 메모, 자유서술형 텍스트, 조사 진행용 변수, 희소하거나 반복되는 세부 문항을 제외했다.
3. 최종 입력으로 인구통계 10개, 기부 정보 습득 경로 12개, 기부 인식·행동 4개, 소득 파생 특성 1개를 선정했다.

| 제외 그룹 | 대표 컬럼 | 제외 근거 |
|---|---|---|
| 식별·검수용 | `NO`, `확인 필요 사항` | 예측 시 사용할 수 없고 개별 응답을 식별할 위험이 있음 |
| 조사 진행·선별용 | `S1`, `S2`, 선문 보조 컬럼 | 조사 절차를 위한 변수로 실제 예측 활용도가 낮음 |
| 자유서술형 | `*_TXT` | 현재 수치형 모델에서 직접 사용할 수 없고 희소성이 큼 |
| 세부·반복 문항 | `문4`, `문6`, `문13`, `문14`, `문20`, `문23` 계열 일부 | 세부 응답이 특성 수를 과도하게 늘리거나 선정된 요약 특성과 중복됨 |
| 원본 소득 | `배문6` | 단위 보정·로그 변환한 `평균 소득(배문6_정리)`로 대체 |
| 최종 선정 외 | `문6_01` | 최종 특성 구성에서 제외 |

### 3.2 결측과 특수 코드 처리

| 대상 | 현재 처리 | 근거 및 주의점 |
|---|---|---|
| `기부 이유(문7)` | 결측과 9997을 하나의 대체 대상으로 두고, 유효 응답 1~5의 관측 비율에 따라 난수 대체 | 0으로 일괄 대체하는 것보다 기존 응답 분포를 유지 |
| `기부 수준 인식(문31)`, `자원 봉사 여부(문40)`, `고향사랑기부제 인지여부(문42)` | 결측을 9997로 통합한 뒤 각 문항의 유효 응답 분포로 난수 대체 | 2,500건이 원천 데이터 블록에 따른 구조적 결측이므로 단순 임의 결측으로 보기 어려움 |
| `종교(배문4)` | 코드가 5 미만이면 유지하고 5·6·9997·9998은 0으로 통합 | 노트북의 현재 구현을 그대로 반영함. 코드북을 통해 범주 통합의 의미를 재확인할 필요가 있음 |
| 최종 잔여 결측 | `fillna(0)`을 방어적으로 적용 | 직전 점검에서 이미 결측 0건이므로 실질적 대체가 아닌 안전장치임 |

난수 대체에는 `np.random.default_rng(SEED)`를 사용하여 같은 입력에서 결과가 재현되도록 했다.

### 3.3 인코딩과 특성 공학

| 대상 | 변환 방법 | 변환 결과 |
|---|---|---|
| `정보습득경로(1)(문3_1)`~`정보습득경로(12)(문3_12)` | 값이 1 이상이면 1, 그 외은 0 | 기부 정보 습득 경로별 선택 여부를 나타내는 12개 멀티핫 특성 |
| `배문6` | 100,000 이상이면 10,000으로 나눠 만 원 단위로 보정 | 단위가 통일된 소득값 |
| `평균 소득(배문6_정리)` | 단위 보정 후 `log1p` 적용 | 큰 소득값의 영향과 우측 편향이 완화된 파생 특성 |
| 나머지 설문 범주 | 원본 숫자 코드 유지 | 현재 XGBoost 입력으로 사용. 명목척도의 코드 순서가 수치적 크기로 해석될 수 있다는 한계가 있음 |

## 5. 모델링용 데이터 구성

| 항목 | 설정 |
|---|---|
| 분리 방식 | `train_test_split` |

### 5.2 모델링 단계의 불균형 보정

다음 항목은 데이터 전처리가 아니라 XGBoost 학습·판정 설정이다.

| 항목 | 현재 설정 |
|---|---|
| XGBoost 타겟 변환 | `기부여부(GUBUN)` 1→0, 2→1 |
| 클래스 가중치 | `scale_pos_weight`에 1.0, 학습 데이터 비율, 해당 비율의 1.5배를 후보로 사용 |

| 임계값 조정 목적 | `기부여부(GUBUN) = 2` Recall을 높이되 정밀도·정확도와의 균형을 별도 점검 |
